High Level Design Document

BoG Assistant
Architecture

A RAG system for Board of Governors meeting documents. Ingests PDFs via OCR, indexes them in a vector store, and answers natural-language queries using a hosted LLM.

01 — System Overview

Architecture at a Glance

Document Store
AWS S3
Raw PDFs stored under pdfs/ prefix. Source of truth for all meeting documents.
Metadata Store
PostgreSQL
Tracks every document and chunk. Enables deduplication, deletion, and document listing.
Vector Store
Qdrant
384-dim cosine vectors from all-MiniLM-L6-v2. Used for semantic similarity search at query time.
Embedding Model
all-MiniLM-L6-v2
Sentence Transformers model. Runs locally on the API server. No external API call needed.
LLM
Groq / LLaMA 3.3 70B
Hosted inference via Groq API. Receives retrieved context + query; generates final answer.
OCR Engine
PaddleOCR
Rasterises each PDF page and extracts text. Handles scanned and digital PDFs uniformly.
Incremental by design. The embedding pipeline checks PostgreSQL before processing any file. Already-embedded documents are skipped — re-running create_vector_embedding.py is always safe.

03 — Pre-processing Detail

What Happens Before a Chunk Reaches Qdrant

📄
PDF → Page Rasterisation
PyMuPDF + PaddleOCR
1
Open PDF with fitz.open() (PyMuPDF). Iterate over every page.
2
Rasterise page to a pixel map via page.get_pixmap(). Converts to numpy array (H×W×N).
3
PaddleOCR runs use_angle_cls=True to handle rotated text. Returns bounding boxes + confidence scores.
4
Concatenate all word strings per page into a single text blob.
🔖
Metadata Extraction
Regex on filename + page text
1
meeting_no — extracted from filename using r"\d{1,3}(?:st|nd|rd|th)". E.g. "45th_BoG.pdf" → "45".
2
item_no — extracted from page text using r"\d+\.\d+". E.g. "Item 3.2" → "3.2". Used for agenda filtering.
3
page — zero-indexed page number from PyMuPDF iterator.
4
source — original filename. Stored in payload for traceability.
🧹
Text Normalisation
Before embedding
1
Whitespace collapse — re.sub(r"\s+", " ", text).strip() removes tabs, newlines, double spaces.
2
Context prefix prepended: Meeting: {no}\nPage: {n}\n{text}. Improves retrieval accuracy by baking meeting context into the embedding.
3
No chunking beyond pages — each page is one chunk. Keeps context windows intact for BoG-style documents.
🧮
Embedding
sentence-transformers → Qdrant
1
Batch encode all page texts for a single document in one call.
2
UUID per point — each chunk gets a uuid4() string. Stored in Qdrant as the point ID and in PostgreSQL chunks.qdrant_id.
3
Qdrant insert — vector of 384 dimensions is inserted in the Qdrant.
4
PostgreSQL write — one documents row + N chunks rows after successful Qdrant upsert.
OCR failure handling: If PaddleOCR throws an exception on a page (corrupt raster, all-black scan), the page returns an empty string and is silently skipped — it does not crash the pipeline.

05 — Query Intelligence

Query Parsing & Routing Logic

Route Type Trigger Example Query Filter Applied Search Method
agenda Regex finds \d+\.\d+ "What happened in item 3.2?" item_no == "3.2" (in-memory) In-memory exact match, fallback substring
latest "latest" / "last" / "recent" "What was discussed in the latest meeting?" meeting_no == max(all) In-memory filter after computing max
single Exactly one number in query "Summary of 45th meeting" meeting_no == "45" In-memory filter
multi Two or more numbers "Compare meetings 44 and 45" meeting_no IN ["44","45"] In-memory union filter
global No numbers, no agenda, no recency "Who chairs the finance committee?" None Qdrant ANN vector search (top_k=50)

Re-ranking after Filter

Scoring Formula
# For each candidate doc: score = 0 # +2 for each query word found score += sum(2 for w in q_words if w in text) # +5 for domain keyword match DOMAIN = ["phd", "finance", "academic", "infrastructure"] score += sum(5 for w in DOMAIN if w in query and w in text) # Top 30 by score sent to LLM
LLM Prompt Structure
# System prompt instructs LLM to: "Answer using context below." "- Extract exact facts" "- Count properly if required" "- Combine multiple chunks" # Context: top-30 chunks # (max 1000 chars each) # Model: llama-3.3-70b-versatile # via Groq hosted inference
06 — Data Stores

Database Schemas & Fields

🪣
AWS S3
Object Storage — Raw PDFs
Object Structure
Bucket string Configured via S3_BUCKET_NAME env var
Key prefix path Always pdfs/{filename}
Body bytes Raw PDF binary content
Access Patterns
put_object WRITE On upload (API or bulk script)
download_file READ During embedding pipeline to temp path
list_objects_v2 LIST Enumerate all PDFs for bulk processing
presigned URL TEMP Generate expiring download links (1hr)
🐘
PostgreSQL
Relational — Metadata & Deduplication
Table: documents
id SERIAL PK Auto-increment primary key
filename TEXT UNIQUE Original PDF filename — deduplication key
s3_key TEXT Full S3 key e.g. pdfs/45th_BoG.pdf
meeting_no TEXT Extracted meeting number e.g. "45"
uploaded_at TIMESTAMPTZ Auto-set to NOW() on insert
Table: chunks
id SERIAL PK Auto-increment primary key
document_id INT FK References documents.id — CASCADE DELETE
qdrant_id TEXT UUID of the matching Qdrant point
page INTEGER Zero-indexed page number in the PDF
item_no TEXT Agenda item if found on this page (nullable)
created_at TIMESTAMPTZ Auto-set to NOW() on insert
🎯
Qdrant
Vector Store — Embeddings & Payload
Collection: bog_documents
id UUID string Generated uuid4 per chunk. Same value stored in PG chunks.qdrant_id
vector float[384] L2-normalised MiniLM embedding of chunk text
Payload Fields (per point)
page_content string Full normalised text of the page chunk
source string Original PDF filename for traceability
meeting_no string | null Meeting number for payload filtering
item_no string | null Agenda item number if found on page
page integer Zero-indexed page number
Collection Config
distance enum COSINE — optimised for normalised embeddings
size integer 384 — all-MiniLM-L6-v2 output dimension
Delete cascade: Deleting a document via DELETE /documents/{id} removes the Qdrant points by UUID list, then deletes the PostgreSQL documents row (which cascades to chunks). The S3 object is intentionally preserved as a backup — call s3_storage.delete_file(filename) manually if permanent removal is needed.
07 — Component Responsibilities

What Each Module Owns

api.py
FastAPI application. HTTP surface of the system — all external requests enter here.
  • Startup: initialises DB, Qdrant collection, OCR, embedder, RAG handler
  • POST /documents — validates, uploads to S3, OCRs, embeds, writes PG
  • POST /query — delegates entirely to RAGHandler
  • GET /documents — reads from PostgreSQL documents table
  • DELETE /documents/{id} — orchestrates Qdrant + PG cleanup
  • GET /health — returns Qdrant collection stats
rag_query_handler.py
All query intelligence lives here. Stateful: holds in-memory payload cache on init.
  • Loads all Qdrant payloads into RAM at startup via scroll_all()
  • _parse_query(): regex routing to 5 query types
  • _filter_docs(): applies the correct filter to the in-memory cache
  • _score_docs(): keyword + domain word re-ranking
  • Sends top-30 chunks as context to Groq LLaMA 3.3
  • Refreshes in-memory cache after new uploads
qdrant_store.py
Thin wrapper around QdrantClient. Handles all vector operations.
  • ensure_collection(): idempotent collection creation
  • upsert_points(): generates UUIDs, wraps PointStruct, batch upserts
  • similarity_search(): query_points() for client >= 1.7, search() fallback
  • scroll_all(): bulk payload fetch for in-memory cache
  • delete_by_ids(): remove points by UUID list
  • collection_info(): stats for health endpoint
db.py
All PostgreSQL operations via psycopg2. Schema initialisation and CRUD.
  • init_db(): CREATE TABLE IF NOT EXISTS for documents + chunks
  • insert_document(): upsert on filename conflict
  • document_exists(): deduplication check before processing
  • insert_chunks(): batch insert chunk rows
  • get_qdrant_ids_for_document(): lookup before deletion
  • delete_document(): cascades to chunks via FK
s3_storage.py
All AWS S3 operations via boto3. Handles both file-path and bytes-based uploads.
  • upload_bytes(): direct bytes upload (API upload path)
  • upload_file(): local path upload (bulk script path)
  • download_to_path(): stream to temp file for OCR
  • list_pdfs(): paginated listing under pdfs/ prefix
  • file_exists(): head_object check
  • presigned_url(): generate time-limited download URLs
create_vector_embedding.py
Offline bulk pipeline. Run once before deployment to seed the vector store.
  • Lists all PDFs in S3 via s3_storage.list_pdfs()
  • Skips already-processed files via db.document_exists()
  • Downloads each PDF to /tmp/, OCRs, embeds, cleans up
  • Writes to Qdrant + PostgreSQL after successful processing
  • Progress bar via tqdm, incremental — safe to re-run
08 — Payload & Response Schema

API Contracts

POST /query — Request & Response

// Request body { "query": "What was decided in meeting 45?", "top_k": 10 // optional, default 10 } // Response body { "text": "<LLM answer string>", "answer": "<same>", "response": "<same>", "message": { "text": "<same>" }, "status": "success" | "error" }

POST /documents — Response

// multipart/form-data, field: "file" // Only .pdf accepted // Success response { "status": "success", "filename": "45th_BoG.pdf", "chunks": 38, // pages embedded "doc_id": 7 // PostgreSQL row id } // 409 if already processed // 422 if no text extracted

GET /documents — Response

{ "documents": [ { "id": 7, "filename": "45th_BoG.pdf", "s3_key": "pdfs/45th_BoG.pdf", "meeting_no": "45", "uploaded_at": "2025-08-17T..." } ] }

Qdrant Point Payload

// Stored alongside every 384-dim vector { "page_content": "Meeting: 45\nPage: 3\n...", "source": "45th_BoG.pdf", "meeting_no": "45", "item_no": "3.2" | null, "page": 3 }
End-to-end delete contract: DELETE /documents/{id} → fetch chunks.qdrant_id list from PG → qdrant_store.delete_by_ids() → db.delete_document(id) (cascades chunks) → refresh rag_handler.all_docs in-memory cache. The next query sees consistent state without a restart.
